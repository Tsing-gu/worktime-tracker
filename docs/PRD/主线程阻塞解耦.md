# 主线程阻塞解耦 PRD

## 1. 背景与问题

### 1.1 问题现象

- **Bug 1**：修改上班时间弹窗、成功提示 QMessageBox 的确认按钮"卡住"，需要重复点击
- **Bug 2**：取消更新后弹窗不关闭，持续显示"正在更新"
- 通用问题：on_tick 定时器触发期间，所有 UI 操作无响应

### 1.2 根因

主线程（Qt GUI 线程）被同步阻塞操作占满，无法处理按钮点击等 UI 事件。

`on_tick`（30s 定时器）在主线程同步执行 `poll_and_record()`，内含多个 `subprocess.run`：

| 调用 | 文件位置 | timeout | 最大阻塞 | 频率 |
|------|----------|---------|----------|------|
| `ioreg -c IOHIDSystem` | system.py:34 | **无** | 无上限 | 每 30s 调两次 |
| `ipconfig getpacket en0` | system.py:113 | 3s | 3s | 每 30s |
| `osascript` (通知) | system.py:191 | 5s | 5s | 事件触发时 |

此外 `_check_update_after_confirm` 中的 `urlopen`（timeout=15s × 2 URL = 最多 30s）也在主线程执行。

v0.13.9 临时方案（`activeModalWidget` 检测跳过轮询）治标不治本：每个对话框都会导致轮询数据丢失，且其他阻塞操作仍未解决。

### 1.3 目标

将所有阻塞操作移到子线程，**主线程永不阻塞**，所有功能互不影响。

## 2. 方案概述

### 2.1 核心思路

将所有阻塞 I/O 操作从主线程同步调用改为子线程异步执行，结果通过 Qt 信号回主线程处理。主线程只负责 UI 渲染和用户交互。

项目已有此模式：`_download_and_install` 中的 DMG 下载已在子线程执行，通过 `QMetaObject.invokeMethod + QueuedConnection` 回主线程更新 UI。

### 2.2 全量阻塞操作排查与处理

**所有功能全部子线程化，确保互不影响：**

| 操作 | 位置 | 阻塞时间 | 处理方式 |
|------|------|----------|----------|
| `ioreg` (HID 读取) | system.py:34 | 无上限 → 加 timeout=5 | ✅ 随 poll_and_record 子线程化 + 加 timeout |
| `ipconfig` (网络检测) | system.py:113 | 最多 3s | ✅ 随 poll_and_record 子线程化 |
| `osascript` (通知) | system.py:191 | 最多 5s | ✅ 子线程发送 |
| `_fetch_feed` (更新检查) | update_service.py:97 | 最多 30s | ✅ 子线程化 |
| `pmset` (回溯上班) | system.py:145 | 最多 5s | ✅ 子线程化 |
| Holiday API (启动时) | holiday_service.py:65 | 最多 20s | ✅ 子线程化 |
| Excel 导出 | export_service.py | <1s | ✅ 子线程化 |
| SQLite 读写 | database.py | <50ms | ⏸ WAL 模式优化即可 |

## 3. 详细设计

### 3.0 前置：SQLite 线程安全修复

**问题**：`Database._get_conn()` 复用连接，默认 `check_same_thread=True`。Repository 在主线程创建，子线程使用会报 `ProgrammingError`。

**修复**（`src/data/database.py`）：
- `sqlite3.connect(self._db_path, check_same_thread=False)` 允许跨线程
- `PRAGMA journal_mode=WAL` 启用 WAL 模式（多读 + 一写不互斥）

**安全性**：
- WAL 模式下读不阻塞写、写自动串行化
- `transaction()` 上下文有 commit/rollback 保证原子性
- 竞态风险（子线程写 vs 主线程写）：SQLite 写锁串行化，30s 间隔碰撞概率极低

### 3.1 轮询子线程化（核心）

**文件**：`src/ui/main_window.py`

```
on_tick()                          # 主线程：仅启动子线程
  └─ Thread: poll_and_record()    # 子线程：ioreg + ipconfig + DB 读写
       └─ Signal: poll_finished    # 信号回主线程
            └─ _on_poll_finished() # 主线程：通知/弹窗/refresh_ui
```

- 新增类信号 `poll_finished = Signal(object)`
- `on_tick` 启动 daemon 线程执行 `poll_and_record`，结果通过 `emit` 回主线程
- `_on_poll_finished` 槽函数处理事件通知、refresh_ui、次日确认弹窗
- **移除** `activeModalWidget` 跳过逻辑
- **osascript 通知移到子线程**：`_on_poll_finished` 中收到 off/target_reached 事件后启动子线程发通知，主线程不阻塞

### 3.2 更新检查子线程化

**文件**：`src/ui/main_window.py`

`on_check_update` 和 `_check_update_after_confirm` 中的 `check_for_updates()` 移到子线程：

- 新增类信号 `update_check_finished = Signal(object)`
- `on_check_update` 启动子线程执行 `check_for_updates`，结果通过信号回主线程
- `_on_update_check_finished` 槽函数：info=None → 失败弹窗；info 非空 → 弹更新确认；info 为空 → "已是最新"
- `_check_update_after_confirm` 同理
- 移除 `on_check_update` 中的 `QMessageBox.information("正在检查中，请稍候...")`（不再需要，UI 不会冻结）

### 3.3 pmset 读取子线程化

**文件**：`src/ui/edit_start_dialog.py`

"从 pmset 读取"按钮点击后：
1. 禁用按钮 + 显示"读取中..."
2. 启动子线程执行 `get_pmset_start_time`
3. 通过 `QMetaObject.invokeMethod + QueuedConnection` 回主线程
4. 恢复按钮 + 回填输入框或弹提示
- `pmset_btn` 改为 `self._pmset_btn` 实例引用

### 3.4 ioreg 加 timeout 兜底

**文件**：`src/utils/system.py:34`

```python
result = subprocess.run(["ioreg", "-c", "IOHIDSystem"], capture_output=True, text=True, timeout=5)
```

即使移到子线程，也加 timeout 防止永久卡死导致子线程泄露。

### 3.5 Holiday API 子线程化

**文件**：`src/ui/main_window.py`（`_on_startup`）

启动时 `HolidayService.ensure_loaded()` 中的 `urlopen`（最多 20s）移到子线程：
- 启动时先 `refresh_ui`（DB 有缓存则直接用缓存数据）
- 子线程异步拉取 holiday API，完成后通过信号回主线程刷新
- 如果缓存已有当年数据，子线程仅静默更新；无缓存时子线程拉取完成后刷新 UI

### 3.6 Excel 导出子线程化

**文件**：`src/ui/main_window.py`（`on_export`）

导出 Excel 时 `wb.save()` 移到子线程：
- 禁用导出按钮 + 显示"导出中..."
- 子线程执行 `exporter.to_excel()`（含 openpyxl 写文件）
- 通过信号回主线程：成功弹"已保存到..."提示，失败弹错误提示

## 4. 不改动的部分

| 组件 | 理由 |
|------|------|
| `refresh_ui` | 只读 DB + 更新 Qt 控件，必须在主线程，<50ms |
| `_check_yesterday_confirm` | 弹模态对话框，必须在主线程 |
| `_show_update_confirm` | 同上 |
| `_confirm_resume` | 同上 |
| 下载 DMG | 已在子线程 |
| SQLite 读写 | <50ms，WAL 模式优化即可 |

## 5. 隐患与风险

| 隐患 | 影响 | 缓解 |
|------|------|------|
| SQLite 跨线程 | 子线程使用主线程创建的连接报错 | `check_same_thread=False` + WAL |
| 跨线程 Qt 操作崩溃 | 子线程直接操作 Qt 控件崩溃 | Signal / QMetaObject + QueuedConnection |
| 竞态写入覆盖 | 子线程写 vs 主线程写 | SQLite 写锁串行化，30s 间隔碰撞极低 |
| 子线程异常未捕获 | 异常不传播到主线程 | worker 内 try/except，emit(None) 降级 |
| osascript 子线程 | 系统通知可能不触发 | 先测试，不正常则回退主线程 |
| Holiday 启动时无缓存 | 首次启动需等待 API | 子线程异步，UI 先用空数据渲染，完成后刷新 |

## 6. 涉及文件

| 文件 | 改动 |

## 7. 验证方式

1. 打开"修改上班"对话框，等待 30s+，确认按钮不卡住
2. QMessageBox 成功提示，等待 30s+，确认按钮不卡住
3. 托盘菜单"检查更新"，确认 UI 不冻结
4. on_tick 期间 UI 仍可交互（进度条/按钮/菜单）
5. DB 有 activity_events 记录（轮询数据正常写入）
6. 触发下班/达标事件，系统通知正常弹出（osascript 子线程）
7. 跨天次日确认弹窗正常弹出
8. "从 pmset 读取"按钮：禁用 + "读取中" → 正常回填
9. 首次启动（无 holiday 缓存），UI 先渲染 → API 完成后刷新
10. 导出 Excel，UI 不冻结，完成后弹"已保存"提示
